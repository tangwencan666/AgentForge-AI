# AgentForge AI 原方案与新基线差异

本次最新需求建立正式 P0 基线。原方案的模型数量、技术选型和实现状态均无法核实，统一标记为“待核对”。此表比较需要明确或替换的架构约束，不将未知内容描述成已有实现或缺陷。

| 领域 | 原方案 | 新 P0 基线 | 后续实施变化 |
| --- | --- | --- | --- |
| 模型数量与职责 | 待核对 | Planner、Coder、Researcher、Reviewer 四个独立槽位 | 建立角色路由和独立配置，不推定原先为八模型 |
| 服务商组合 | 待核对 | 同服务商多个模型或四个不同服务商 | 通过 Provider Adapter 统一调用与 usage |
| 凭据 | 待核对 | credential_reference 引用受保护凭据 | 写入接口不回显；响应、Git、日志禁止明文 Key |
| Mock | 待核对 | 显式 Mock 模式和结果标识 | UI、SSE、记录均保留 Mock 标签，失败不偷偷转 Mock |
| 技术栈 | 待核对 | FastAPI、LangGraph、LangChain、React | LangGraph 管工作流，LangChain 管适配和检索 |
| 协作 | 待核对 | Planner → Worker → Reviewer；无依赖 Worker 并发 | DAG 校验、资源冲突串行、分支汇聚、有限反馈循环 |
| 异步与状态 | 待核对 | PostgreSQL 真相源与检查点，Redis 调度 | 租约、fencing、outbox、恢复及幂等副作用账本 |
| 执行上限 | 待核对 | 总 deadline、取消、迭代、Token、预算硬约束 | 并发调用前原子预留，所有重试和审查计入上限 |
| 沙箱 | 待核对 | 真 Docker 执行器，安全策略由服务端锁定 | Docker 不可用安全失败，禁止宿主机回退 |
| 网络与权限 | 待核对 | none 网络、非 root、只读根、cap_drop ALL、seccomp | 创建及执行前验证实际策略，Agent 不接受配置覆盖权 |
| 预热 | 待核对 | 有界预创建容器，单次使用 | 不重复使用已执行容器；状态不明销毁并补充新容器 |
| MCP | 待核对 | 服务端 Tool Gateway 强制入口 | 白名单、鉴权、参数校验、审计、额度及高风险审批 |
| Skills | 待核对 | 版本、启停、依赖、权限和审批 | 自我进化仅生成惰性候选，不自动下载或执行 |
| 人工审批 | 待核对 | 持久化审批，绑定操作哈希和有效期 | 审批恢复后再次鉴权；Reviewer 没有授权能力 |
| 上下文 | 待核对 | Context Engineering 与租户范围 RAG | Token 裁剪、来源、可信度、脱敏、工具输出不升级为指令 |
| 前端与 SSE | 待核对 | 六个 Center 页面，持久化事件流 | 重连回放、租户授权、Mock 提示、取消和审批操作 |
| 可观测性 | 待核对 | Token、成本、延迟、错误与执行关联 | 价格版本、估算标识、脱敏追踪、审计与业务日志分离 |
| 自动化验收 | 待核对 | 需求映射到具体测试和发布门禁 | 真实 Docker 集成测试不能用 Mock 替代或跳过后宣称通过 |

## 对旧规划的处理

后续若提供旧文件，仅核对可复用的业务目标、目录、数据与兼容性。旧描述与本次安全基线冲突时，以本次明确要求为准；涉及数据迁移和破坏性变更须单独设计。当前不进行旧仓库迁移、其他项目修改或旧实现删除。
